# 공개 포트폴리오 유지·보안 가이드

이 저장소는 **비공개 원본 프로젝트에 대한 공개용 설명 공간**입니다.

## 신규 프로젝트를 추가할 때

1. `projects/<project-slug>/README.md`를 생성하고 메인 README 표에 링크합니다.
2. 문제 정의 → 구현한 것 → 기술/설계 선택 → 실제 검증 → 후속 계획 순서로 정리합니다.
3. 기능 상태를 `운영 확인`, `구현·테스트 완료`, `개발 중`, `계획`으로 명확히 구분합니다.
4. 공개 가능한 더미 데이터 스크린샷이 생기면 `assets/screenshots/`에 추가합니다.
5. 프로젝트별 README를 업데이트할 때 확인 기준일을 남깁니다.

## 공개 전 필수 확인

- [ ] API 키, 비밀번호, OAuth 토큰, DB 연결 문자열, 배포 Secret이 없다.
- [ ] 개인 금융정보, 계좌번호, 투자 포지션, 게임 계정 식별자를 포함하지 않는다.
- [ ] 접근 제어가 필요한 운영 URL, 상세 운영 식별자, 내부 로그를 공개하지 않는다.
- [ ] 이미지에 사용자명, 계정 정보, 개인 알림, 식별 가능한 데이터가 보이지 않는다.
- [ ] 회사 내부 업무 정책, 고객 정보, 미공개 자료를 사용하지 않는다.
- [ ] 서비스가 실제로 배포·검증된 범위와 개발 계획을 구분한다.
- [ ] 외부 API·게임·서비스의 저작권 및 이용 조건을 검토한다.
- [ ] 더미 데이터임을 필요한 경우 명시한다.

## 도구 사용의 표현

AI 코딩 도구는 구현·리팩터링·테스트·문서화 과정의 보조 도구로 기술합니다. 프로젝트 소개는 문제 설정, 도메인 판단, 구조적 의사결정, 검증 과정, 배운 점 중심으로 작성합니다. 실제로 검증하지 않은 수치나 성과는 작성하지 않습니다.
